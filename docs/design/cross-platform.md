# Cross-platform: required fixes

Status: audit of 2026-10-27. The app will be built for Windows, macOS and Linux (targets and distribution: [Cinematic grading and CGI effects, section 3.6](cinematic-grade-and-vfx.md#36-platforms)). Today it runs on Windows only. This document lists everything found that must change, where it is, and how to fix it.

**Severity.**

- **Blocker**: the app does not start or a feature fails on macOS or Linux.
- **Wrong result**: it runs, but the output differs between systems or breaks when a project moves between them.
- **Verify**: probably fine; confirm on each platform and add a test.
- **Polish**: works, but against platform conventions.

**Summary.** The engine (TypeScript, FFmpeg, models) is mostly portable already. The main problems are in three places:

- **The desktop app**, which is WPF and Windows-only throughout.
- **Project files**, which store absolute Windows paths for generated media.
- **Fonts**: Arial and Arial Black are the defaults everywhere and are missing on Linux.

## Progress

Items marked **Done** in the tables below are implemented. What was built, by item:

- **E4 Done.** `engine/tools/appdirs.ts`: `appDir("cache" | "data")` follows each system's conventions; `defaultModelsDir()` and `defaultFontsDir()` keep the `AVE_MODELS_DIR` and `AVE_FONTS_DIR` overrides. On first use per process, `models` and `fonts` move out of the old `~/.cache/videditbridge` (only when the new folder does not exist yet).
- **C1 Done.** Bundled open fonts in `assets/fonts/` at the package root (shipped in the npm package, OFL license texts beside them): Arimo, Archivo Black, Gelasio, Anton, Cousine and Comic Neue. Every render goes through `prepareFonts` (`engine/tools/fonts/index.ts`), which copies them into the fonts folder, always passes `fontsdir`, and replaces the system fonts named in `FONT_REPLACEMENTS` (Arial, Arial Black, Georgia, Impact, Courier New, Comic Sans MS) when this machine lacks them. That covers text layers, captions and graphics (resvg, with `replaceSvgFonts`). Every default in schemas, caption styles, components, templates and the thumbnail now names the bundled font. A packaged app can point at its own copy with `AVE_BUNDLED_FONTS_DIR`. All 33 templates were rendered with the new fonts (`FULL_RENDER=1`) and their contact sheets checked on 2026-10-28: no clipped or overflowing text. Components are covered only through those templates.
- **C2 Done.** Linux user fonts in `$XDG_DATA_HOME/fonts` (default `~/.local/share/fonts`) are found, and system folders are now scanned recursively (Linux sorts fonts into subfolders, so none were found before).
- **B1 Done.** `toProjectPath` (`engine/core/util.ts`) and `withProjectPaths` (`engine/core/operations.ts`). The session applies them on open and on every commit, so generated media is stored relative to the project folder with forward slashes. `EditorSession.projectPath` is the helper for single files. Renders apply the same step, so a project saved on Windows renders on Linux. `validateProject` warns about absolute and backslash paths. Existing projects get the new paths in memory when opened and on disk at their next save. The projects in `projects/` have not been rewritten yet: cinematic-reel still stores absolute `.render` paths until its next save.
- **B2 Done.** `validateProject(project, { baseDir })` checks each media file on disk with exact case (`fileOnDisk`), reports a missing file as an error. A case-only difference is a warning where the system ignores case (Windows, macOS), and an error naming the file on disk where it does not (Linux, as CI showed). `get_project` and `ave validate` pass the folder. `import_media` stores the name as it is spelled on disk.
- **B3 Done.** `escapeFilterPath` escapes for both levels of FFmpeg parsing: `\`, `'` and `:` get a backslash at the option level, and `'` is written `'\''` at the graph level. It now turns backslashes into `/` only on Windows, since `\` is a legal name character elsewhere. Before this, a `'` in a path broke the filter, and backslashes in Linux names were changed. `test/repo/cross-platform.test.ts` runs `lut3d` through a filter script with LUT files in folders named with spaces, `'`, brackets, `,`, `;` and non-ASCII characters, plus `:` and `\` on macOS and Linux.
- **D1 Done.** `engine/tools/render/selftest.ts`: `checkFfmpeg` checks the build's filter, encoder and decoder lists against `REQUIRED_FFMPEG` (the renderer's filters, the export and cache encoders, and decoders for phone, WebM and Ogg media) and reports optional parts (`rubberband`) separately. `ave check` prints the report and exits 1 when something is missing. The host logs it at startup when the build is incomplete, and `test/repo/cross-platform.test.ts` fails on an incomplete build, so CI checks it on every target.
- **G1 Done (green on all systems, 2026-10-28).** `.github/workflows/ci.yml` runs on Windows, macOS arm64 (`macos-14`) and Ubuntu 22.04. Each job runs `npm ci` (so the optional native packages must install), typecheck, `ave check`, `docs:check` and the unit tests, and builds the app. The first runs found three real problems, all fixed: a case-only file name mismatch is an error on Linux, generated docs were compared without ignoring CRLF line endings, and Windows 8.3 short names (`RUNNER~1`) broke `fileOnDisk`. The repository is private, so Actions minutes cost money, and macOS minutes count about ten times Linux ones. To save minutes, pull requests run Linux and Windows only, while pushes to `main` add macOS. The full `npm test` with renders and models runs weekly (Sunday) and on demand, and keeps `test/.output` for 7 days when it fails. A newer run on the same branch cancels the older one, and jobs have time limits. macOS x64 was dropped after its first green run: Apple no longer makes Intel Macs. Add `macos-15-intel` back to the matrices for an occasional check, or build x64 when packaging.
- **E2 Done (each computer measures for itself).** `createOrtSession` in `engine/tools/vision/faces.ts` serves all three models (faces, person cutout, sound classes). Graphics cards differ widely between computers, so no default is fixed. On first use of a model, its first runs go through both this system's GPU provider (DirectML on Windows, CoreML on macOS, CUDA on Linux) and the CPU: one untimed warm-up each, then 3 timed runs. The CPU's answer is returned during measuring, so results never depend on it. Then the faster provider is kept and saved in `<model>.provider.json` next to the model file, with the timings. If a provider fails to load or to run, the CPU is chosen. Delete the file to measure again (for example after a new graphics card). `AVE_ORT_PROVIDERS` overrides the choice: `cpu`, `gpu` or a list such as `dml,cpu`. On the development PC, which has a weak GPU (Windows, 2026-10-28), the CPU won both: faces 36 ms against 38 ms on DirectML, and the sound model failed on DirectML (a Reshape node).
- **C3 Done.** `engine/tools/fonts/scripts.ts`: `SCRIPT_FONTS` maps Japanese, Korean, Chinese, Arabic, Hebrew, Devanagari, Bengali, Tamil, Thai and emoji to Noto fonts (OFL; monochrome Noto Emoji, since libass and resvg draw no color emoji). Chinese characters follow the text: Japanese when it has kana, Korean when it has Hangul. `prepareFonts(fontsDir, project)` finds the scripts in the project's text, downloads only the Noto fonts it needs into the fonts folder (once), and reads each named font's character map (`readFontCoverage`). `applyFontFallback` then inserts `\fn` switches in the ASS text only where the font in effect has no glyph, so a font that covers a script keeps it and every system falls back the same way. Graphics pass the same Noto files to resvg. A frame with Latin, Japanese, Chinese, Korean, Arabic, Hebrew, Devanagari, Thai and emoji text rendered correctly on 2026-10-28. Offline, a missing Noto font is skipped and libass falls back as the system does.
- **F1 Done.** `engine/host/main.ts` handles `SIGTERM`, `SIGHUP` and `SIGINT` the same way as stdin closing: it finishes pending saves, then exits, which removes `.host.json`.
- **A1 Done.** The app is Avalonia UI 11.3 (`net10.0`, no Windows-only parts) and builds for Windows, `linux-x64` and `osx-arm64`. The view models, `EngineClient` and the JSON-RPC protocol are kept. `App.axaml` and `MainWindow.axaml` are rewritten with the same layout and UI rules (960x460, dark neutral, blue primary, icons, no emoji or long dashes). Style triggers became classes and selectors, and the activity glow is a rotating conic gradient. `Controls/TimelineView.cs` draws with Avalonia's `DrawingContext`. `MessageBox` became a small dialog in the app's style. Checked on Windows on 2026-10-28: a project opened, frames showed while scrubbing, a preview rendered and played, a spot was picked on the playing video, the projects screen and the native folder dialog worked, and closing stopped the engine and removed `.host.json`.
- **A2 and A3 Done (LibVLC).** `Playback/Player.cs`: LibVLCSharp 3.10 with VLC 3.0, linked dynamically and shipped unmodified (`THIRD-PARTY-NOTICES.md`). VLC's libraries come from `VideoLAN.LibVLC.Windows` and `VideoLAN.LibVLC.Mac`; Linux uses the system's libvlc, and the viewer says to install VLC when it is missing. `VideoPlayer` decodes into a buffer through LibVLC's video callbacks and copies each frame into a bitmap the viewer shows like a still image. A native video window would cover the spot marker and other overlays, and this keeps them on top on every system. `AudioPlayer` plays voice and music auditions. LibVLC starts on first playback, not at app start. Still to do: compare startup and seeking on macOS and Linux.
- **A4 Done.** Open folder, import media and export use Avalonia's `StorageProvider`, which shows each system's own dialogs (with macOS type identifiers and MIME types in the filters).
- **A5 Done.** Icons come from the bundled Fluent UI System Icons font (MIT, `Assets/Fonts`), and `Icons.cs` maps every glyph that was a Segoe code. The UI font is Segoe UI on Windows and the bundled Inter (OFL, `Avalonia.Fonts.Inter`) elsewhere. The timeline uses the window's font. The UI rule in CLAUDE.md is updated.
- **A6 Done.** `EngineClient` first looks for an engine shipped with the app: `Contents/Resources/engine` in a macOS bundle, or `engine` next to the executable elsewhere. That is either a single executable `ave-host` or a Node runtime with `dist/host/main.js`. Projects then go to `Documents/VideditBridge`. In development it uses the repository as before (`AVE_ENGINE_DIR`, or a folder above the app) and finds Node on PATH, in Homebrew, Volta and nvm folders, or through `AVE_NODE`. Apps opened from the macOS Finder or a Linux menu do not get the shell's PATH. Arguments go through `ArgumentList`, so paths are quoted correctly everywhere. Producing the bundled engine is part of packaging (G2).
- **A7 Done.** `Packaging/`: macOS `Info.plist`, the Linux `.desktop` file, an icon set (16 to 1024 px from `AppIcon.svg`) and a README on where each piece goes. The Windows manifest and `Assets/AppIcon.ico` stay for Windows. `.icns` is made with `iconutil` when packaging on macOS.
- **G4 Done.** CLAUDE.md, the README and the UI style rules describe the Avalonia app. CI builds the app on all four targets.
